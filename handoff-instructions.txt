声の記憶帳 - 引き継ぎ指示書
==========================
作成日: 2026-06-30
リポジトリ: https://github.com/somanakahashi-ops/Voice-Cloning


■ プロジェクト概要
------------------
個人(本人)の過去の音声サンプルから「声紋」を複数(年代・時代別)登録し、
人生史のナレーション原稿を本人の声で読み上げるWebアプリ。
声紋は年齢・時代によって複数セット保持できる設計(例: 20代の声、晩年の声)。
個人利用が前提だが、将来的に複数人・商用展開する可能性もゼロではないため、
ライセンス面はクリアな構成を選んでいる。


■ これまでに確定した設計判断(重要・変更しない前提で進めてよい)
----------------------------------------------------------------

1. 商用利用可能なライセンスのみを使う
   - XTTS-v2(Coqui)は不採用。理由: Coqui Public Model License(CPML)が非商用限定。
     さらにCoqui社は2024年1月に倒産しており、商用ライセンスを購入する手段すら
     現在は存在しない。
   - 採用技術は KokoClone (https://github.com/Ashish-Patnaik/kokoclone)。
     Apache 2.0ライセンスで商用利用可能。Kokoro-ONNX(高速TTS)と
     Kanade Tokenizer(ゼロショット声質変換)を組み合わせたプロジェクト。
   - Kanade Tokenizer自体のライセンスは個別確認すること(未確認のまま採用している)。

2. 生成パイプラインは「2段階構成」で確定
   Step 1(読み上げ生成): テキスト → Kokoro(素のTTS、固定ボイス) → 下書き音声
   Step 2(声で仕上げる): 下書き音声 + 声紋(参照音声) → KokoClone内
                          Kanadeの「Audio→Cloneモード」(声質変換) → 最終音声

   理由: テキストの正確さ(発音・間)と声質を別々にチューニング・デバッグできる。
   下書き音声は声紋非依存なので、同じ章を複数の声紋(年代違い)で
   試聴比較する用途にも使い回せる。

   KokoCloneのAudio→Cloneモードは文字起こし不要、任意の長さの録音に対応
   (VRAM対応の自動チャンク分割: chunked_voice_conversion関数)。

3. 声紋は「1人に対して複数」のデータモデル
   過去の実録音(古いビデオ、ボイスメモ等)をそのまま参照音声として登録する想定。
   現在の声から過去の声を推定生成する「年齢変換」は対象外(技術的に未成熟なため)。
   音質劣化(ノイズ、低サンプリングレート等)はあえて許容する方針。
   「当時の質感が乗る」ことはむしろ良しとする。


■ 現在の実装状況
------------------

1. フロントエンド(完成、ローカルでは動作確認可能)
   ファイル: voice-narration-prototype.jsx (React, 単一ファイル)
   - 声紋ライブラリ(録音 / アップロード、カセットテープ風UI、年代タグで色分け)
   - 章エディタ(タイムライン形式、章ごとに本文編集)
   - Step1「読み上げを生成」ボタン → Step2「この声で仕上げる」ボタンの2段階UI
   - 実際のバックエンドAPI(後述)にfetchで接続する形まで実装済み
   - バックエンドが繋がらない場合はエラーバナーを表示する作りになっている
   - API_BASE定数(デフォルト http://localhost:8000)を環境に応じて変更すること

2. バックエンド(雛形のみ、TTS/声質変換の中身は未実装)
   ファイル: backend/main.py (FastAPI)
   - 声紋CRUD: POST/GET/DELETE /api/voice-profiles
   - 章CRUD: POST/GET/PATCH/DELETE /api/chapters
   - 生成エンドポイント:
       POST /api/chapters/{id}/generate-draft  (Step1)
       POST /api/chapters/{id}/apply-voice     (Step2)
       GET  /api/chapters/{id}/status          (ポーリング用)
   - run_kokoro_tts() と run_voice_conversion() の2関数が NotImplementedError。
     関数内のコメントに実装イメージ(kokoro-onnx / KokoCloneの使い方)を
     書いてあるので、それを参考に実装すること。
   - データはインメモリ(プロトタイプ用)。本番ではDBに置き換える前提。
   - ジョブはBackgroundTasksで簡易非同期にしているのみ。
     同時リクエストが増える運用ではCelery+Redis等のジョブキューへの
     差し替えを推奨。
   - ストレージはローカルディスク。本番ではS3等への差し替えを推奨。

   詳細手順は backend/README.md に記載済み。


■ 後継セッションへの依頼事項(優先順)
----------------------------------------

1. このリポジトリ(somanakahashi-ops/Voice-Cloning)に
   voice-narration-prototype.jsx と backend/ 一式をpushする
   (まだリポジトリは空の可能性あり。要確認)

2. backend/main.py の run_kokoro_tts() を実装する
   - kokoro-onnx パッケージをインストール
   - 日本語ボイスモデル(kokoro-v1.0.onnx, voices-v1.0.bin)を取得・配置
   - 関数内コメントのサンプルコードを参考に実装

3. backend/main.py の run_voice_conversion() を実装する
   - https://github.com/Ashish-Patnaik/kokoclone をセットアップ
   - Kanade Tokenizerのライセンスを個別確認(未確認のまま)
   - 関数内コメントのサンプルコードを参考に実装
   - chunked_voice_conversion関数を使うこと(長尺音声でのVRAM対策のため)

4. 実機(GPU環境)での疎通確認
   - この設計のTTS・声質変換は、CPUでは現実的な速度で動かない可能性が高い
   - クラウドGPU(RunPod、Lambda Labs等)での実行を想定しておくこと
   - claude.ai/code(Claude Code on the web)経由で操作する場合、
     ネットワークアクセス設定で pip install 等のパッケージ取得を
     許可するモードを選ぶこと。GPUの有無は環境依存のため要確認。

5. 声紋登録時の前処理(ノイズ除去・正規化)を実装する
   - 現状 create_voice_profile() 内は前処理なし、固定文言のquality_noteを返すのみ
   - 過去の劣化した音声(古いビデオ、ボイスメモ等)が入力される前提のため、
     最低限のノイズ除去・サンプリングレート統一は入れた方がよい
   - ただし「当時の質感を残す」方針なので、過度なクリーンアップはしないこと

6. 長文の章をStep1で生成する際の文単位分割・結合処理
   - 現状未実装。長いナレーション原稿を一括でKokoroに投げた場合の
     安定性は未検証


■ 判断に迷ったら参照すべき方針
--------------------------------
- ライセンスは常に「商用利用可能」を最優先する(将来の展開可能性を残すため)
- 過去の音声の劣化・ノイズは「当時の質感」として許容する(過度な補正はしない)
- 声紋は人物1人に対して複数(年代・時代別)持てる設計を崩さない
- Step1(読み上げ)とStep2(声質変換)の分離構成を崩さない
  (本文修正時の部分的再生成、声紋違いでの聴き比べに必要なため)
